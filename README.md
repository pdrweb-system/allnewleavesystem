# ระบบใบลาออนไลน์ v2 — โรงเรียนวัดปรีดาราม (มณีศิริวรรณ)

หน้าเว็บ static บน **GitHub Pages** + ฐานข้อมูล/ล็อกอิน/ไฟล์บน **Supabase** (โปรเจกต์ `leave-system`,
ภูมิภาคสิงคโปร์, แพ็กเกจ Free) แจ้งเตือนเข้ากลุ่ม LINE เดิม แทนระบบ Google Apps Script + Google Sheet

- ครูยื่นใบลาจากมือถือ เซ็นชื่อบนจอ แนบใบรับรองแพทย์ได้ (ไม่บังคับ)
- อนุมัติตามลำดับ หัวหน้าฝ่ายบุคลากร → รองผู้อำนวยการ → ผู้อำนวยการ (ข้ามขั้นไม่ได้) ทุกขั้นถูกบันทึกเวลาและผู้กด
- ใบลา A4 สร้างสดจากข้อมูล พิมพ์/บันทึก PDF จากเบราว์เซอร์ได้ ลายเซ็นผู้อนุมัติขึ้นเฉพาะขั้นที่อนุมัติแล้ว
- เซิร์ฟเวอร์เป็นผู้คำนวณวันลา ตรวจวันซ้อน โควตา และสิทธิ์ทั้งหมด หน้าเว็บแก้ข้อมูลตรง ๆ ไม่ได้

## สิ่งที่ต้องทำเองก่อนเปิดใช้ (ทำตามลำดับ)

### 1. ตั้งค่าล็อกอินใน Supabase Dashboard
โปรเจกต์ `leave-system` → **Authentication → Sign In / Providers**
- ปิด **Allow new users to sign up** (บัญชีสร้างโดยแอดมินเท่านั้น)
- Email: ปิด **Confirm email**, ตั้ง **Minimum password length = 6** (ต้องไม่เกิน 6) และ **Password Requirements = No required characters**
  (รหัสเข้าใช้เป็นตัวเลขล้วน 6 หลัก ถ้าตั้ง Letters and digits ไว้ ระบบจะสร้างบัญชี/ตั้งรหัสไม่ได้)

> ระหว่างที่ยังไม่ปิด signup คนนอกสมัครบัญชีได้แต่จะไม่เห็นข้อมูลใดเลย (ไม่มี profile = RLS ปฏิเสธทั้งหมด
> มีชุดทดสอบยืนยัน) แต่ควรปิดทันที

### 2. สร้างบัญชีแอดมินคนแรก
ทุกคนเข้าระบบด้วย **รหัสเข้าใช้ตัวเลข 6 หลักอย่างเดียว** ไม่มีชื่อผู้ใช้ แอดมินเป็นผู้ตั้งรหัสให้ ผู้ใช้เปลี่ยนเองไม่ได้
- ติดตั้งใหม่: ทำตาม `supabase/seed/bootstrap_admin.sql` (Dashboard → Authentication → Users → **Add user**
  แล้วรัน SQL ในไฟล์) จากนั้นรัน `supabase/seed/set_login_code.sql` เพื่อตั้งรหัสเข้าใช้ของแอดมิน
- บัญชีที่สร้างไว้ก่อนเปลี่ยนมาใช้รหัส 6 หลัก (เช่น `ben`): รัน `supabase/seed/set_login_code.sql`
  ใน **SQL Editor** โดยแก้ `v_user_code` เป็นรหัสอ้างอิงของบัญชี และ `v_code` เป็นรหัส 6 หลักที่ต้องการ (รหัส 8 หลักที่ตั้งไว้เดิมยังใช้ล็อกอินได้)

> ระบบเก็บรหัสเข้าใช้แบบเข้ารหัสทางเดียว (ใครก็อ่านคืนไม่ได้ รวมถึงแอดมิน) และใช้แฮชของรหัสเป็นอีเมลภายในของ Supabase Auth
> (`k…@leave.pdr.invalid` — `.invalid` เป็นโดเมนสงวน ไม่มีใครรับอีเมลได้) จึงหาบัญชีได้จากรหัสอย่างเดียว และรหัสซ้ำกันไม่ได้

### 3. เปิดเว็บด้วย GitHub Pages
repo → **Settings → Pages** → Source: *Deploy from a branch* → เลือก branch หลัก / `(root)` → Save
เว็บจะอยู่ที่ `https://pdrweb-system.github.io/<ชื่อ repo>/` (ใช้ค่านี้เป็น `SITE_URL` ในข้อ 4)

> workflow `keep-alive` (กันโปรเจกต์ Free ถูก pause) ทำงานเฉพาะบน branch หลักของ repo

### 4. LINE (ทำได้เฉพาะเจ้าของบัญชี LINE OA)
1. **ออก channel access token ใหม่** ใน LINE Developers Console แล้ว **ยกเลิก token เดิม** (อันเดิมเคยถูกฝังในโค้ดและในแชต)
2. ใส่ secrets ใน Supabase Dashboard → **Edge Functions → Secrets** (ห้ามใส่ใน repo หรือในฐานข้อมูล)

| ชื่อ | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | token ใหม่ |
| `LINE_GROUP_MAIN` | group ID กลุ่มหลัก (ขึ้นต้นด้วย `C...`) |
| `LINE_GROUP_FINAL` | group ID กลุ่มเพิ่มเติมที่ได้รับการ์ด "ผอ. อนุญาตแล้ว" นอกเหนือจากกลุ่มหลัก คั่นด้วย `,` เช่น `Cกลุ่มที่2` (ใส่กลุ่มหลักซ้ำก็ได้ ระบบไม่ส่งซ้ำ · ไม่ตั้ง = ส่งกลุ่มหลักกลุ่มเดียว) |
| `SITE_URL` | URL เว็บจากข้อ 3 |

3. ทดสอบ: ยื่นใบลาทดลอง แล้วดู **ตั้งค่า → การแจ้งเตือน LINE ล่าสุด** (สถานะ "ส่งแล้ว"/"ล้มเหลว" พร้อมสาเหตุ กด "ส่งซ้ำ" ได้)

ข้อความในกลุ่มมีชื่อผู้ลา ประเภท วันที่ จำนวนวัน และสถานะ **ไม่มีเหตุผลการลาและเหตุผลที่ไม่อนุมัติ**
แจ้งเมื่อ: ยื่นใหม่ · หัวหน้าฝ่าย/รองฯ อนุมัติ (ส่งต่อขั้นถัดไป) · ผอ. อนุญาต (ส่งทุกกลุ่มใน `LINE_GROUP_FINAL`) · ไม่อนุมัติ
ส่ง LINE ไม่สำเร็จไม่ทำให้การยื่น/อนุมัติล้ม

### 5. ตั้งค่าเริ่มต้นในหน้าเว็บ (เมนู ตั้งค่า / ผู้ใช้)
- **วันหยุด**: กด **"ดึงวันหยุดราชการ"** เพื่อดึงวันหยุดราชการปีนี้และปีหน้าจาก calendar.kapook.com (ตรวจแล้วเลือกเพิ่ม
  เฉพาะวันหยุดราชการ ไม่รวมวันหยุดเฉพาะธนาคาร) แล้วเพิ่มวันหยุดโรงเรียนเอง (วางหลายวันพร้อมกันได้) — ระบบไม่นับวันเหล่านี้เป็นวันลา
  ใบที่ยื่นไปแล้วไม่ถูกคำนวณใหม่ จึงควรกรอกก่อนเปิดใช้ และก่อนรันสคริปต์ย้ายข้อมูล
- **โควตา**: ใส่ตัวเลขตามระเบียบของโรงเรียน (ต่อรอบ) และเลือก ไม่ตรวจ / เตือน / ห้ามยื่นเกิน — ตอนนี้ยังไม่ได้ตั้ง
- **ข้อความบนใบลา**: ชื่อโรงเรียน หัวกระดาษ ตำแหน่งผู้อนุมัติ ความเห็นรองฯ
- **ผู้ใช้**: "นำเข้าหลายคน" (วางรายชื่อจาก `users_plan.csv` ของสคริปต์ย้ายข้อมูล) หรือ "+ เพิ่มผู้ใช้" ทีละคน
  ใส่รหัสเข้าใช้เอง หรือเว้นว่างให้ระบบสุ่มเลข 6 หลัก (แนะนำ) · ครูใช้เลข 6 หลัก ส่วนหัวหน้าฝ่าย/รองฯ/ผอ. ตั้งรหัสเองได้ทุกแบบ (ไม่จำกัดความยาวและตัวอักษร) แต่ต้องไม่สั้นกว่า Minimum password length ที่ตั้งไว้ใน Auth settings แจ้งครูเป็นรายคน (อย่าส่งในกลุ่ม)
  ระบบไม่รับรหัสที่เดาง่าย (เลขซ้ำ เลขเรียง) และรหัสที่มีคนใช้แล้ว (ใช้วันเกิดเป็นรหัสได้ แต่เดาง่าย แนะนำให้ระบบสุ่ม)
- **ลายเซ็นผู้อนุมัติ**: ปุ่ม "ลายเซ็น" ของหัวหน้าฝ่าย รองฯ และ ผอ. (PNG พื้นโปร่งใสสวยที่สุด) — ผู้อนุมัติที่ยังไม่มีลายเซ็นกดอนุมัติไม่ได้

### 6. ย้ายข้อมูลจากระบบเดิม
ใช้สคริปต์ `legacy_import.py` (ส่งให้ในแชต ไม่ได้อยู่ใน repo ตาม SPEC) รันในเครื่องที่มีไฟล์ `ระบบข้อมูล.xlsx`:
```bash
pip install openpyxl
python3 legacy_import.py "ระบบข้อมูล.xlsx" --inspect      # ดูโครงชีตก่อน
python3 legacy_import.py "ระบบข้อมูล.xlsx" --out out        # ได้ out/users_plan.csv
# แก้ users_plan.csv: บทบาท hr/deputy/director, แอดมิน (คอลัมน์แรกเป็นรหัสอ้างอิง ใช้จับคู่ใบลาเดิม อย่าลบ)
# → นำเข้าในหน้า ผู้ใช้ → "นำเข้าหลายคน" ระบบสุ่มรหัสเข้าใช้ให้ทุกคน (จดหรือพิมพ์รายการก่อนปิด)
python3 legacy_import.py "ระบบข้อมูล.xlsx" --out out --plan out/users_plan.csv   # ได้ out/import_leaves.sql
```
รัน `out/import_leaves.sql` ใน SQL Editor — ผลลัพธ์สุดท้ายเป็นตารางตรวจสอบ: จำนวนใบต้นทาง/ปลายทาง,
ใบที่นับวันใหม่ได้ไม่ตรงกับไฟล์เดิม และยอดวันลาต่อคนต่อประเภทที่ไม่ตรงกับชีต `Total`
(ส่วนที่ต่างเพราะเปลี่ยนกติกาโดยตั้งใจ เช่น ระบบเดิมนับใบที่ไม่อนุญาตด้วย จะขึ้นในตารางนี้ให้ตรวจ ไม่ถูกแก้เงียบ ๆ)
- ใบลาที่ย้ายมาไม่มีไฟล์ลายเซ็น (เฟส 1 ไม่ย้ายไฟล์) แต่เก็บลิงก์ PDF เดิมไว้ให้กดดูจากหน้ารายละเอียด
- รันซ้ำได้ ใบที่นำเข้าแล้วจะถูกข้าม · โฟลเดอร์ `out/` เป็นข้อมูลส่วนบุคคล ห้าม commit และลบเมื่อเสร็จ

| แจ้งเตือน LINE ไม่ไป | ตั้งค่า → การแจ้งเตือน LINE ล่าสุด → ดูสาเหตุ / "ส่งซ้ำ" |

**สำรองข้อมูล** (แพ็กเกจ Free ไม่มีการสำรองอัตโนมัติ Supabase แนะนำให้ export เอง) อย่างน้อยเดือนละครั้งและก่อนปิดภาคเรียน:
1. สรุป → ส่งออก Excel ทุกรอบ (อ่านง่าย แต่ใช้กู้ระบบไม่ได้)
2. ฐานข้อมูลทั้งหมด รวมบัญชีผู้ใช้: ติดตั้ง Supabase CLI และ Docker Desktop · คัด connection string แบบ **Session pooler**
   จากปุ่ม **Connect** บน Dashboard แล้วแทน `[YOUR-PASSWORD]` ด้วยรหัสผ่านฐานข้อมูล (ลืม → รีเซ็ตที่ Database → Settings)
   รันในโฟลเดอร์ส่วนตัวนอก repo:
   ```bash
   supabase db dump --db-url "<connection string>" -f roles.sql --role-only
   supabase db dump --db-url "<connection string>" -f schema.sql
   supabase db dump --db-url "<connection string>" -f data.sql --use-copy --data-only -x "storage.buckets_vectors" -x "storage.vector_indexes"
   ```
   วิธีกู้คืน: [Backup and Restore using the CLI](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)
   (เมื่ออัปเกรดเป็น Pro จะมีสำรองรายวันที่ Dashboard → Database → Backups)
3. ไฟล์ลายเซ็น/ใบรับรองแพทย์ไม่อยู่ในไฟล์ข้อ 2: Dashboard → Storage → ดาวน์โหลดจากแต่ละ bucket
เก็บไฟล์สำรองในที่ส่วนตัวเท่านั้น (มีข้อมูลสุขภาพและรหัสผ่านที่เข้ารหัสแล้ว) ห้ามใส่ใน repo

**โปรเจกต์ถูก pause** (เว็บโหลดข้อมูลไม่ได้): Dashboard → โปรเจกต์ → Restore แล้วตรวจว่า workflow
`keep-alive` ใน GitHub Actions ยังทำงาน (Actions → keep-alive → Run workflow เพื่อทดสอบ)

- **วันที่ยื่น** = วันนี้ตามเวลาไทย เซิร์ฟเวอร์กำหนด · ยื่นย้อนหลังได้ · ทุกวันที่ลาต้องอยู่ในรอบการลาที่ตั้งไว้
- **วันซ้อน**: ยื่นวันที่ซ้อนกับใบเดิมที่ยังไม่ถูกยกเลิก/ไม่อนุมัติไม่ได้
- **โควตา** (ถ้าตั้ง): นับใบที่อนุญาตแล้ว + ที่รออนุมัติในรอบเดียวกัน
- **ลำดับอนุมัติ**: หัวหน้าฝ่าย → รองฯ → ผอ. · ผู้อนุมัติยื่นลาเองข้ามขั้นของตัวเอง ·
  **ผอ. ไม่ยื่นใบลาในระบบนี้** · ไม่อนุมัติต้องใส่เหตุผลและจบทันที · ผอ. เลือกวันที่อนุญาตได้ (ค่าเริ่มต้นวันนี้)
- **ยกเลิก**: เจ้าของยกเลิกได้จนกว่าจะมีคนพิจารณา · ประวัติการพิจารณาแก้/ลบไม่ได้
- **ลบใบลา**: เจ้าของลบได้เฉพาะใบที่ยกเลิกแล้ว (หน้าหลัก → ใบลาของฉัน → ปุ่ม "ลบ") ลบถาวรพร้อมไฟล์ลายเซ็นและใบรับรองแพทย์ที่แนบ กู้คืนไม่ได้ ใบที่ยกเลิกไม่ถูกนับในยอดลาอยู่แล้ว จึงไม่กระทบสถิติ
- **บัญชีแอดมิน**: ไม่มีเมนู "หน้าหลัก" และ "ยื่นใบลา" ล็อกอินแล้วเข้าหน้า "จัดการผู้ใช้" เลย ถ้าแอดมินจะยื่นใบลาให้สร้างบัญชีในบทบาทครูอีกบัญชีหนึ่งแล้วล็อกอินด้วยรหัสนั้น (ตรวจที่หน้าเว็บ ฐานข้อมูลไม่ได้ห้าม)
- **หน้าแรกตามบทบาท**: หัวหน้าฝ่ายบุคลากร รองผู้อำนวยการ และ ผอ. เปิดหน้า "อนุมัติใบลา" เป็นหน้าแรก · รองฯ และ ผอ. ไม่มีเมนู "หน้าหลัก" และ "ยื่นใบลา" (หัวหน้าฝ่ายยังมีและเข้าได้จากเมนู) · ครูเปิดหน้าหลัก (ตรวจที่หน้าเว็บ ฐานข้อมูลไม่ได้ห้ามรองฯ ยื่นใบลา)
- **หน้า "สรุป"** ไม่แสดงบัญชีบทบาทหัวหน้าฝ่ายบุคลากร รองผู้อำนวยการ และ ผอ. ในตาราง (ซ้ำกับบัญชีครูของคนเดียวกัน) ตัวเลขการ์ดด้านบนยังนับทุกใบ
- **สถิติบนใบลาและหน้าหลัก**: "ลามาแล้ว" = ใบที่ ผอ. อนุญาตแล้ว ของคนเดียวกัน ในรอบเดียวกัน ที่เริ่มลาก่อนใบนี้ ·
  "ครั้ง" นับในรอบของวันเริ่มลา "วัน" นับเฉพาะวันที่อยู่ในรอบ (ใบที่คาบเกี่ยวสองรอบแบ่งวันถูกต้อง) ·
  "ลาล่าสุด" = ใบที่อนุญาตแล้วล่าสุดก่อนใบนี้
- **ลายเซ็นผู้อนุมัติ** ขึ้นบนใบลาเฉพาะขั้นที่ผู้นั้นอนุมัติแล้ว และใช้ไฟล์ลายเซ็น ณ เวลาที่กด (เปลี่ยนลายเซ็นภายหลังไม่กระทบใบเก่า)
- ความเห็นรองฯ ตั้งต้นเป็น "เห็นควรอนุญาตดำเนินการตามคำขอ" (ระบบเดิมสะกด "เห็นความอนุญาต…") แก้ได้ในตั้งค่า

เพิ่มเติม: บัญชีที่ถูกปิด (หรือบัญชีเก่าที่ยังไม่ได้ตั้งรหัสเข้าใช้ใหม่) เรียก RPC และอ่านข้อมูลอื่นไม่ได้ (ตรวจที่ฐานข้อมูล ไม่ใช่แค่หน้าเว็บ) ·
ปิดบัญชี = แบนใน Supabase Auth ด้วย · การกระทำของแอดมินถูกบันทึกในตาราง `admin_audit` ที่แก้/ลบไม่ได้และผู้อนุมัติทุกคนเห็น ·
หน้าเว็บกันการถูกฝังใน iframe และไม่ส่ง Referrer

**คำเตือน 5 รายการใน Security Advisor** (`0029 authenticated_security_definer_function_executable`) สำหรับ
`submit_leave`, `decide_leave`, `cancel_leave`, `delete_leave`, `resend_line_notification` — ตั้งใจ: 5 ฟังก์ชันนี้ต้องเขียนตารางที่หน้าเว็บ
ไม่มีสิทธิ์เขียน จึงต้องเป็น `SECURITY DEFINER` ทุกตัวตรวจผู้เรียก (ล็อกอิน · บัญชีเปิด · ไม่ใช่บัญชีเก่าที่ค้างตั้งรหัส · บทบาท/เจ้าของ) ก่อนทำงาน
และมีชุดทดสอบครอบคลุม RPC ที่อ่านอย่างเดียวเป็น `SECURITY INVOKER` ให้ RLS กรองซ้ำ

**คำเตือน Leaked Password Protection** (ตรวจรหัสผ่านกับรายการรหัสที่เคยรั่วของ HaveIBeenPwned) เปิดได้เฉพาะแพ็กเกจ Pro ขึ้นไป
และไม่จำเป็นกับรหัสเข้าใช้ที่แอดมินตั้งให้ (ผู้ใช้ไม่ได้เลือกรหัสเอง จึงไม่มีการใช้รหัสซ้ำกับเว็บอื่น)

**ข้อควรรู้ของการล็อกอินด้วยรหัส 6 หลักอย่างเดียว** (เลือกเพื่อให้ครูใช้ง่าย): ไม่มีชื่อผู้ใช้เป็นด่านที่สอง
รหัส 6 หลักมีให้เดาเพียง 1,000,000 แบบ และคนที่เดาถูกจะเข้าบัญชีเจ้าของรหัสนั้นได้ทันที (รหัส 8 หลักมี 100 ล้านแบบ ปลอดภัยกว่ามาก)
ความปลอดภัยจึงอยู่ที่ ใช้รหัสสุ่ม (ไม่ใช้วันเกิด/เลขจำง่าย — ระบบบล็อกเฉพาะเลขซ้ำและเลขเรียง) · แจ้งรหัสเป็นรายคน ·
Supabase จำกัดจำนวนครั้งที่ลองเข้าระบบต่อเครื่อง (Dashboard → Authentication → Rate Limits) ควรตรวจว่าไม่ได้ตั้งไว้สูงเกินไป ·
ถ้าสงสัยว่ารหัสหลุด หรือเห็นความพยายามเดารหัสใน Authentication → Logs ให้ "ตั้งรหัสใหม่" ทันที
